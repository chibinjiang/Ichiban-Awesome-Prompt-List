# Evaluation Specification

## 目标

评估 Prompt 是否在同一组任务上比旧版本更有效，而不是评价某次输出是否“看起来不错”。

## 评估维度

每个维度 0～2 分：

### Correctness

- 0：关键结论错误或无法执行
- 1：部分正确
- 2：核心结论正确

### Completeness

- 0：遗漏主要要求
- 1：覆盖部分要求
- 2：覆盖主要要求

### False Positive

- 0：大量无依据问题或错误判断
- 1：存在少量误判
- 2：没有明显误判

### Output Format

- 0：未遵循格式
- 1：部分遵循
- 2：完整遵循

### Actionability

- 0：建议不可执行
- 1：建议需要大量补充
- 2：建议清晰、可执行

### Consistency

- 0：重复执行结果差异很大
- 1：有一定波动
- 2：结果基本稳定

## 解释规则

总分最高 12 分。

- 10～12：在当前测试集上表现良好
- 7～9：可用，但应继续观察
- 0～6：需要修改或重新定义任务

这些阈值只是项目内部工作规则，不代表跨模型、跨任务的绝对质量。

## 对比原则

1. 同一测试集比较 Prompt 版本。
2. 尽量保持模型、参数和上下文一致。
3. 记录失败案例，而不只记录平均分。
4. 不要只增加测试中容易通过的案例。
5. 记录人工评价者和评价时间。
6. 对自动评分结果进行抽查。
